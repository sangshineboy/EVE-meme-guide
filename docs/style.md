# 去 AI 味：风格体检

`npm run style:check` 扫全部词条，挑出最像 AI 写的那些条，并给出该先改的句子。

## 为什么是这几个指标

2026-11 做过一次同口径对比：166 条词条 vs `参考文献/` 里 63 篇真人文本（B 站文案 + N 老板小作文，12.4 万字）。每万字出现次数：

| 指标 | 词条 | 真人 | 倍数 |
| --- | --- | --- | --- |
| 破折号 `——` | 18.9 | 2.5 | 7.6× |
| 分号 `；` | 40.1 | 8.9 | 4.5× |
| 「不是 A，而是 B」 | 2.5 | 0.3 | 8× |
| 正文括注 | 6.7 | 2.5 | 2.7× |
| 年份/具体数字 | 12.8 | 38.4 | 只有 1/3 |
| 第一人称「我」 | 14.2 | 114.5 | 只有 1/8 |

前三个是**句子构造习惯**，跨体裁可比，也是最好改的：AI 爱在一句话里左右平衡（插入语、并列、转折），人写东西是往前推的。

## 怎么判定单条

词条正文中位数只有 181 字，密度会被一两处放大成天文数字，所以**单条用次数**，密度只在全站汇总里算：

| 硬指标 | 触发条件 |
| --- | --- |
| 破折号插入语 | ≥ 2 处 |
| 分号并列 | ≥ 2 处 |
| 「不是 A，而是 B」 | ≥ 1 处 |

| 软提示 | 触发条件 |
| --- | --- |
| 正文括注 | ≥ 2 处 |
| 整条没有年份/数字 | 字数 ≥ 150 且 0 处 |

软提示不下判决：有些梗本来就没有年份可写。

## 用法

```bash
npm run style:check                 # 汇总 + 最重的前 10 条
npm run style:check -- --all        # 全部超标条目
npm run style:check -- --slug kfc   # 单条细看
npm run style:check -- --json       # 程序用
```

报告工具，**不卡构建**，退出码恒为 0。现有基线：166 条里 32 条触发硬指标（19%），全站密度破折号 20.3、分号 43、不是而是 2.7（每万字）。

## 被点到了怎么改

1. **破折号**：多半是想补一句解释。改成逗号、句号另起一句，或者干脆删掉——解释常常是废话。
2. **分号**：两句并列摆平。改成两句独立的话，或者只留一句，另一句扔掉。
3. **「不是 A，而是 B」**：这是最典型的 AI 腔，把「A 不重要、B 才重要」的判断硬塞给读者。直接说 B，让事实自己像 B。
4. **括注**：把括号里的内容并进正文或删掉。
5. **没有数字**：回 `npm run rag -- "关键词"` 找一条具体的时间、数量、原话填进去——这既是去 AI 味，也是 `AGENTS.md` 的「不编造」。

## 边界

- 它只测**句式**，不测内容真假，也不测「好笑」。一条指标全绿但通篇空话的词条，它照样放过。
- 阈值是按「明显高于真人基准」设的，不是「AI 平均值」——按平均值卡，一半词条都不合格，没有可操作性。
- 想从根上换语气（而不是逐条修），顺序是：风格卡 + few-shot → 补具体细节 → 最后才谈 LoRA。**别拿现有 AI 词条当微调集**，那是把 AI 味当成标准答案。
